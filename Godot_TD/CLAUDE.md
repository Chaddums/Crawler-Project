# Vine Logic TD — Project Reference

*Single source of truth for Claude instances and project context. Last updated: 2026-10-18.*

---

## What Is This Game?

A tower defense in canyons: enemies walk the canyon floors to your Spire, your towers stand on the walls above them, and BIT fights down in the canyon. (It began as a programmable-logic TD where the vine network was the maze; the campaign maps no longer allow mazing.) Sensors detect enemies, fire signals along connections to turrets. You are BIT, an ancient AI cleanup script deployed by AXIS, a dismissive corporation that acquired BIT without understanding what it holds. You always lose. The question is how much you extract before you fall.

**One-liner:** "Mine everything you can before they take it all."

**Core reframe:** Not survival — extraction. Not pass/fail — optimization. Resources scale exponentially with wave depth. Every run extracts something. No run is wasted.

**Status:** Continuous extraction loop implemented. Core systems (vine network, mining building, BIT, wave/surge spawning, continuous wave curve, extraction scaling, milestone events, 2 planet themes) are solid. Floor layer removed. S4 meta layer (territory unlocks, suits, boss runs) implemented — data persistence, game flow, and UI screens built. Between-runs loop complete: debrief screen (resource transfer + suit capture) → meta hub (command center with territory/suits/relics/start-run nav) → sub-screens → next run. Scene transitions use TransitionManager (fade in/out). Ascendants fight as bosses (below); the narrative rewrite and node unlock shop are greenfield.

Note: The vine logic circuit system is one possible defense implementation, not core to the game. Level 1 towers should work by default without signal chains. Signal chains are an advanced/optional system.

**Canonical hierarchy:**
```
Run > Planet (1-3) > Wave (1-N continuous) > Surge (dynamic) > Enemy
```

**Address format:** `P#-W#-S#` in all logs, comments, data.

---

## The Core Strategic Axis

```
Mine Resources → fund vine nodes, infrastructure → your NETWORK carries you
Mine Materials → fund character abilities, upgrades → your CHARACTER carries you
```

Mining Building toggles between modes. Cannot do both simultaneously. This is THE decision.

## Conventions

- **Engine:** Godot 4.6 C#, namespace `JunkyardTD`
- **Stitch CEF UI** — primary screens use Stitch HTML rendered via godot-cef (see `docs/STITCH_WORKFLOW.md`). Code-built fallback for when CEF is unavailable. Some screens still code-built CanvasLayer pending CEF rewrite.
- **Singletons:** `ServiceLocator` for services, `GameEvents` static event bus
- **Constants** in `Constants.cs` — no magic numbers in code
- **All tuning in JSON** — never hardcode enemy counts, HP, timing
- **Colors:** `BitPalette.cs` for player/harvester/tower. `PlanetTheme.Current` for enemies/terrain
- **Node types** defined in `Enums.cs`, data in `VineNodeData.cs`
- **Characters** (BIT, enemies) are rigged FBX driven by `CharacterAnimator`. Models without usable clips get a procedural gait/bob, deaths without a death clip get a procedural roll, skin offsets are normalised at load, and `AssetLibrary.GetFacingYawOffset` turns models not authored facing +Z. Check with the `anim` / `anim-sheets` suites.
- **Planet looks** live on `PlanetTheme` (`ConfigureEnvironment`, `ConfigureLights`, accents, converted-ground colour). Scrapyard = dusk (low orange sun, cyan player accent); Grid Prime = two-tone (cyan world, orange player, red/magenta enemies). Player-owned things (towers, converted decor) wear a fresnel rim in the player accent via `BitPalette.ApplyAccentRim` (a `MaterialOverlay`, so imported materials stay untouched).
- **Towers:** each buildable tower is built from `Data/Towers/{id}.json` (`TowerSheet`, `TowerLook` under `Scripts/VineLogic/Towers/`, keyed by `VineNodeData.Id`): an optional pedestal in the KB3D textures with a band in the tower's colour, kit models (fitted by footprint, height or scale, sub-meshes hidden by name) and shapes (box, cylinder, prism, sphere, torus, capsule) in surfaces `concrete`, `panel`, `trim`, `hazard`, `white`, `dark` (triplanar KB3D building textures), `copper`, `chrome`, `tar` or `glow`. Parts marked `aim` (or a kit model's `aimNodes`) turn toward what the tower shoots and scan slowly when idle; the barrel direction and tip are found from the meshes (snapped to the model's axes) unless the sheet gives `muzzle`; shots leave from `TowerLook.MuzzleGlobal`. `recoil` kicks the aiming parts back on each shot, `punch` parts shoot out (the Pneumatic Ram), `spin` parts turn. Wall parts with `face`/`link` show only without/with a wall next door on that side, so lines of walls join. A tower must fit its cell at its `restYaw`. The build ghost uses the same sheet. Healthy towers show no HP bar and no status pip. Other nodes use the kit model mapped in `VineNode.GetModelPathForNodeType`; `TowerMeshes` is the fallback if a sheet fails to load. Kit models (KB3D) are recentred on their footprint at load (`AssetLibrary.RecenterFootprint`; the GLBs keep props at their kit-layout positions, tens of units from origin). A placed node's origin is `NODE_ORIGIN_HEIGHT` above its cell's highest corner (plus `ELEVATED_PLATFORM_HEIGHT` on an elevated cell); models are offset down by it. Cells sloping more than `FOOTING_MIN_SLOPE`, and elevated cells, get a footing (`VineNode.AddFooting`) down to the lowest ground within `NODE_FOOTPRINT_MARGIN` of the cell. Tower models fit inside their cell (`fidelity` allows 0.05).
- **Ground:** `VineGrid.GetWorldHeight` returns the drawn surface (two triangles per cell, split from (x+1,z) to (x,z+1), and the outer apron), so anything placed with it sits on what the player sees. Field decor is seated on the lowest corner of its cell and stretched to keep its top (`SeatDecor`, after any terrain change); flat overlays (channel floor, data stream, pit) are terrain-following quads (`DrapedCellQuad`). Enemies snap to the ground every frame and keep their body circle (`_bodyRadius`, capped at 0.45 of a cell) out of solid cells (`StayOutOfSolids`); Ghosts are exempt. The Spire is seated on the lowest ground under its footprint (`VineHarvester.SeatOn`). A Spire's model, its optional platform (`model.base`, a Data/Towers sheet) and its autocannons (`autocannonConfig.sheet`, each a `TowerLook` on the platform's corners that tracks its own target) sit under one `SpireModel` root; the health bar sits just above the model. The Arcanist's shield is a hex-panelled dome (`ShieldDome`) that collapses with a flash when the shield breaks and fades back in on recharge.
- **Player mech progression:** BIT earns XP during a run (any kill, its own kills, cleared waves), levels up (level n costs `xpBase` x `xpGrowth`^(n-1): 55 x 1.25, about 210 XP to level 4, 830 to 8, 1,420 to 10; at 10 x 1.4 the bots were in the Strider by W3, the Titan by W11 and at the top by W19, and the playtest said "you level up too fast and you don't start as BIT"; crate XP is a third of what it was and grows like Resources, since at 55 x 1.2 the first safe room's haul put BIT up four levels at once), (health, damage, size, outline and glow, plus parts at set levels) and bolts on gear for every perk picked, all from `Data/Mechs/bit.json` (`MechSheet`, `MechProgression`, `MechAppearance` under `Scripts/VineLogic/Mech/`). Nothing carries between runs. Gear hangs off `BoneAttachment3D` sockets so it moves with the animation, and wears BIT's hull, glow or lit "metal" materials so it swaps at the dome edge and flashes with the body. Gear with a `muzzle` is a gun: shots leave from it in turn, with its own size, colour and speed. Every offered perk needs gear in the sheet (`mech/sheet/every_perk_has_gear`). A new mech is a new sheet plus its sockets; `Constants.PLAYER_MECH_ID` picks BIT's. **BIT's body** (`BitBody`, 2026-10) is the Mike robot (`sparkplug.fbx`, a Quaternius rig with real arms and hands) in BIT's colours: `BitBody.HullShader` turns `Mike_4_Texture.png` into dark gunmetal (its brightness kept as panel detail, read raw so the paint is judged as painted) with the painted parts glowing in the eye colour, a fresnel rim and a white outline inside the dome; outside, near-black with the planet accent. Two glowing lenses on the face are the level-1 "Eyes" tier. `BitBody.PrepareClips` gives BIT its clips by name: Idle, Walk, Run, Attack_R (Punch), Attack_L, Shoot_R (Shoot), Shoot_L, Slash, Hit, Death, Cheer; the `_L` clips are the right-arm clips mirrored (`BitBody.Mirror`: each bone takes its partner's skinning reflected across the body). `BitArms` (a `SkeletonModifier3D` on the skeleton) sweeps both arms back for the naruto run and points an arm at a target while BIT shoots, holds the lance on it or punches on the run. Gear is authored in Mike's T-pose units (5.35 tall); hand and forearm sockets ride the forearm bones with X along the arm. Before, BIT was the round LilRobot, whose stub arms couldn't hold anything: ice gauntlets floated beside it, the lance hung off its side and gear was a pile of boxes.
- **BIT's frames (2026-10, `VinePlayerFrames.cs`, `frames` in `Data/Mechs/bit.json`, `MechFrame`):** the playtest asked for BIT to stay the main character and get into a bigger bot as it levels. At level 4 BIT climbs into the Strider (`clunker.fbx`, the same Quaternius rig and clips as BIT's body, 2.0 tall: two arm guns, faster fire, longer reach) and at level 8 the Titan (`gun_robot.fbx`, 2.1 tall: gatling arms, shells that burst, more health, takes 30% less, slower). With BIT's growth that is about 2.2 and 2.7 world units, a little over a canyon wall; the playtest found them "way too big" at 2.7 and 3.4 (the Titan stood about 5 tall with BIT on top at 6.7), and the seat scale, sink, body radius, muzzle reach and lift came down with them. Each frame wears BIT's hull (`ApplyFrameHull`: its texture through `BitBody.HullShader` with its own `paint_lo`/`paint_hi`, so the Titan's blue panels stay dark) and swaps it at the dome edge; BIT itself stays BIT (its gear, level parts and relic gear stay on it) and rides on top, scaled to `seat.scale` and put on the top of the head its seat bone carries (`SeatPilot`: `FindHeadTop` takes the vertices skinned to that bone, and every frame, after the frame's animation, BIT is put on the highest of them under its stance as posed now, `HeadTopUnder`), then sunk to its waist by `seat.offset`, so it rides in the head like a pilot in a hatch. The playtest saw BIT floating over the Strider's head: it stood on a hand-set offset from the bone, and standing on top its thin legs read as nothing; the frame's holder takes the facing, lean and sway BIT's body took (`Body`). The frame has its own Q, E and R (`MechAbility`, kinds salvo, slam, repair, overclock, built on the same `Blast`, `Repair` and `OverclockTowers` BIT's own use): Strider Rocket Salvo, Field Repair, Overdrive (also +50% to its own guns); Titan Earthshaker, Bulwark (repairs and fortifies), Overclock Grid (also +40% to its gatlings). Stats in `stats` (health added in place of the last frame's, damage, rate, reach, speed, share of the sprint kept, damage taken), shots in `shot` (`splash` bursts on what it hits), `lift` raises a model whose clips stand lower than its rest pose, `BodyRadius` keeps it out of rock. Climbing in is celebrated, BIT says its line on the comms, the HUD names the frame and the next one ("BIT · STRIDER  LV 5  ·  Titan at 8"). Head Start puts BIT straight into the frame its level calls for. A relic weapon still replaces the frame's guns. The Titan shares its model with the Deep Current Ascendant (in its own blue and white); new art would part them. The playtest found the Titan "trying to fly away" whichever way it was walked: `gun_robot.fbx`'s Run (it has no Walk; Walk plays Run) was authored on a root node turned 95 degrees from every other clip's, so it ran on its face, and its 4.9-unit stride was never taken out because `StripRootMotion` measured a node's keys in the node's own frame (the root node is scaled 0.01, so the stride read as 0.05); it ran 19 units off its spot a loop and snapped back. Now `StripRootMotion` measures in the parent's frame, and `CharacterAnimator.UprightLikeIdle` turns a walk or run clip whose root bone is more than 60 degrees off the Idle's back to stand where and how the Idle stands, with its travel taken out and the loop centred on the Idle's spot (only that clip in the game is touched: the Deep Current Ascendant runs upright now too). `mech` checks each frame (rides it, BIT's hull, BIT on top, BIT in the head to its waist through idle, walk, run and a shot (`SeatGapNow` skins the head on the CPU), on the ground, walks each way on the canyon floor with its hips on its spot, BIT high and near (`walks_on_the_ground`), shots from its barrels, each ability works, level 1 is on foot); `mech-sheets` with `MECH_SHEETS=frames` renders them, running from the side too; with a display `mech` also saves `{frame}_standing.png`/`{frame}_walking.png`.
- **Tower stats:** a tower's `Damage` is damage per second. Each shot deals `GetEffectiveDamage(interval)` and the timer rearms with `GetEffectiveFireInterval(interval)` (`VineNode.Rearm`, which carries the overshoot so a fast tower keeps its rate), so damage and fire-rate bonuses (perks, the Overclock Relay's +25% to both, component slots, relics) reach every tower. Flak's damage is per target. Bands checked by `balance`: the Junk Turret is the best single-target buy per cost; Scatter, Tesla and Flak beat it on groups of five; nothing falls under 0.3x its single-target value or over 2.6x its group value.
- **Perks** are registered in `VinePerkData.cs`. Perks with a `Tower` change how that tower plays (Arc Conductor, Tar Pools, Hydraulic Stun, Cluster Shells, Piercing Rail, Relay Mesh, Saturation Fire; constants `PERK_*` in `Constants.cs`) and are drawn at 0.35 weight until that tower is built. They also change the tower: `perkParts` in its `Data/Towers` sheet pop onto every standing and new tower when picked (`TowerLook.ShowPerk`), and BIT bolts on matching gear. Stuns use `VineEnemy.ApplyStun` (bosses and commanders take `STUN_BOSS_FACTOR` of it).
- **Screens between runs:** the title's PLAY goes to the Command Center (home base; it used to go to planet select, so a new player never saw it until a run ended). The hub's Deploy card starts the campaign's next site (`TerritoryManager.Campaign`/`NextSite`, `MetaHubScreen.DeployNext`) and shows its region's progress pips; "Choose planet & site" goes the long way. The debrief says where the campaign stands (`DebriefScreen.CampaignLine`) and **what happened** (`RunRecord`, fed by the battle as it plays and begun with each battle scene): a headline on how it ended and why ("The Spire fell on wave 23. The Iron Sovereign got through 2 times and did 46% of the damage to the Spire. Brute landed the last blow."; a secured site, a boss down, or a run ended from the pause menu say so), the numbers (waves cleared, time, kills and BIT's share, bosses down, leaks and the Spire damage they did, towers built and wrecked, BIT's level and frame, Resources earned, BIT's downs, crates and relics), a bar a wave of the Spire's health at each clear, and up to eight moments (a frame, a boss down, a relic, a Gold Cache or better, the Spire under half, the last blow). On the web page (`showReport`) it takes the place of the old lives/mode/planet numbers and the page scrolls; the code-built screen has it as `WhatHappened`. The playtest finished a run and nothing explained what had happened (`ui.debrief_says_what_happened`). The web pages (title, planet select, debrief, hub, relics, suits) watch godot-cef's `render_process_terminated` (`CefHelper.WatchCrash`) and reload once, then fall back to the code-built screen; each also sits on a dark backdrop (`CefHelper.AddBackdrop`, also the clear colour) and is checked 2.5 s after it opens (`CefHelper.WatchPaint`/`LooksBlank`): a page that never drew is made again once, then the code-built screen takes over (that was the grey screen after a run). The debrief and planet select take Enter and Esc. The territory screen falls back to planet 1's sites for a planet without any, draws its own backdrop (`GridBackdrop`) and offers "Play next". `RunGuide` is a getting-started checklist on the first runs (dismissed state in `user://ui.cfg`).
- **Effects:** every transient effect is pooled particles (`VfxParticles`, one per battle scene: a MultiMesh per kind, sparks, glows, smoke, debris, ground rings and lightning segments, simulated in C# and pushed as one buffer a frame; looks in `VfxLook`, shaders and textures generated in code). `VfxFactory` builds effects from them: impacts, directional muzzle flashes, explosions, tracers, Tesla arcs, tar splats, shoves, buff motes, energy bursts, deaths. An effect makes no nodes, meshes or materials; projectiles are one node with a particle trail. A particle ages at most 1/30 s on its first step, so a slow frame still draws a short effect once (the Storm Lance's beam vanished unseen at 5 fps). The Conversion Dome's motes and wisps are particles too (`ConversionDome.AmbientParticles`). `AutoFadeNode`, `DeathFragment` and `VfxCache` remain for the intro cinematic, and `VfxCache`'s shared meshes for the Spire autocannon's shells. **Enemies break apart** (`VfxFactory.SpawnBreakApart`, from `VineEnemy.Die`): the model goes at once and a dozen chunks of its body (its colour and bare metal, sized by its body) fly out and up, bounce and settle on the ground as they cool, with glowing gold scrap popping up like coins, sparks and smoke (bosses twice as much); it used to play its death clip and sink into the ground ("they should break apart into materials"; `vfx/enemy_breaks_apart`). An Ascendant still falls, since its body stays for BIT. The debris and glow pools are 1024 and 768.
- **Settings** (`GameSettings`, `SettingsScreen`, from the title and the pause menu; `user://settings.cfg`, never written by tests): volumes (buses SFX, Music, Voice), fullscreen, VSync, frame cap, Graphics (Low/Balanced/High: the sun's shadow cascades 1/2/4 and the mesh LOD threshold 6/3/1 px; four cascades drew a big field five times over), screen shake, gunner mouse speed, damage numbers, route preview, BIT auto-fire, and NEW ACCOUNT (two presses: `AccountReset` moves vine_meta.json, suits.json, relic_inventory.json, loadouts.json and ui.cfg, with their backups, into `user://old_account_{date_time}/`, refuses saves until the game restarts (`SafeFile` checks `AccountReset.Blocking`, so the old account in memory isn't written back on the way out) and restarts it; moving the files back restores the old account; `ui/new_account_*` checks it). The battle fits the sun's shadow reach to the camera (`VineBattleScene.FitShadowsToCamera`).
- **Big moments and feedback:** `Celebration` puts a site secured, a region taken, an Ascendant down, a relic, perk points and strikes in the middle of the screen (queued, Layer 28). `ResourceFlyout` shows every drop: "+N" where it fell and chips that fly into the Resources counter, which pulses. `DamageNumbers` (pooled Label3D) sums hits on an enemy into a number every 0.5 s, 16 at most at once (a busy field drops ordinary ones; big hits and BIT's take the oldest slot), small with a thin edge (26 to 40 px, 48 at a time, covered the fight), shows hits on BIT in red, and carries the small tags over towers (what boosts them, ranks) and rallied enemies. An enemy touching BIT hits for its own attack (at least `CONTACT_DAMAGE_MIN` times the climb's damage, x`CONTACT_DAMAGE_MULT`, commanders and bosses x`CONTACT_DAMAGE_BIG_MULT`) once a second; it was 5 + 5% of the enemy's health, which grew with the climb and the AXIS threat to 140 a touch at W25, so no BIT could fight up close. BIT getting hurt reddens the screen edge (stronger for bigger hits, pulsing below 30%). The HUD's OBJECTIVE card says what secures the site and the region's progress (`GameManager.ObjectiveLine`, `TerritoryManager.RegionProgressLine`).
- **BIT's controls and attacks:** WASD is screen-relative (`TDCamera.ScreenToGround`, so it follows the camera's orbit). BIT naruto runs the moment it moves (the Run clip looping, `CharacterAnimator.PlayCustomLooping`, with `BitArms` sweeping the arms back and the body leaning in) and stays in it through attacks and key changes; shots leave its palms (`hand_r`/`hand_l`, or a gun's muzzle) with that arm pointed at the target, the hands taking turns; a punch or shot clip holds the walk and idle off until it ends (`PlayAction`). BIT shoots the nearest enemy in range by itself; holding the left mouse button (not while placing, not over UI) fires where the mouse points instead (`VinePlayer.FireAimed`: the first enemy near the line, out to range). `EffectiveDamage`, `EffectiveAttackSpeed`, `EffectiveRange` and `AbilityPower` are the base stats (which level-ups raise) times the Spire upgrades. Aimed shots reach `BIT_AIMED_RANGE` (44); the naruto run ramps to +`NarutoSpeedBonus` of move speed over `NARUTO_RAMP_TIME`. BIT's body (`BIT_BODY_RADIUS`) is kept out of rock, props, pits and breakable walls (`VinePlayer.StayOutOfTerrain`, `BlocksBit`); its own towers stay walk-through. Down, BIT comes back beside the Spire after `VINE_PLAYER_RESPAWN_TIME` (announced), and the camera waits there (WASD used to fly the camera round the map until then). BIT heals: `BIT_REGEN_SHARE` of max health a second once unhit for `BIT_REGEN_DELAY` s, `BIT_DOCKED_REGEN_SHARE` inside the Spire, and Repair Pulse patches it by `ABILITY_REPAIR_BIT_SHARE`. Repair Pulse puts `ABILITY_REPAIR_SPIRE` (12) back on the Spire, `ABILITY_REPAIR_SPIRE_PER_WAVE` (30) a wave at most (both times ability power; `VinePlayer.SpireRepairLeft`), and says when the Spire is patched as far as it goes: kept on cooldown it put back about 110 a wave and the Spire read full until the wave that killed it.
- **The Spire station** (`Scripts/VineLogic/Spire/SpireStation.cs`, tuning in `Data/spire_station.json`): within reach, F opens the Spire menu (`SpirePanel`, code-built): Spire upgrades (Guns, Plating, Reach) cost Resources, BIT upgrades (Weapon, Trigger, Reach, Core) cost Materials banked at the Spire, plus refill BIT's Materials and train BIT (banked Materials to XP). G climbs in: BIT is hidden and safe, straight into first person (gunner view), the left button fires the cannon (F or G climbs out). Spire Guns mounts a visible gun per level, four to a collar on brackets up the Spire's column (any role, `VineHarvester.SetExtraGuns`, each fires on its own; on a ring round the foot at 0.7 across they stood among the towers and read as nothing), the Bruteforge's platform guns are 1.55x their sheet (`autocannonConfig.scale`), every Spire gun hits `gunGrowthPerWave` (8%) harder a wave (`SpireStation.GunDamageMult`; a flat 12 a shot did nothing past W10) with bigger, faster shells, and the wave card counts the bought guns too, Plating adds armour plates round the base (`SetPlating`), Reach shows its new range on the ground. **Strikes** (`strikes` in the JSON): one-shot weapons bought as charges with Resources and fired with 1, 2, 3 where the mouse or crosshair points (else at the thickest knot of enemies): Orbital Lance (huge damage, small circle), Cluster Barrage (shells spread evenly over an area, landing in a random order; fully random spots left a knot at the centre under one shell about a third of the time), EMP Burst (stun, strips shields, breaks Empowerer tethers); damage grows a share a wave and follows the health ramp, and the HUD lists ready charges. Holding F (a tap opens the menu) repairs a damaged Spire with BIT's own Materials; it is never automatic, since BIT starts the run beside the Spire. Materials mode banks `dropShare` of every enemy drop at the Spire and mines `spireRateMult` times faster (before 2026-10 Materials mode only grew a number nothing spent). Right-click acts on a click's release (`ClickGuard`): right-drag turns the camera.
- **Gunner view:** climbing in starts in first person from the Spire's top (V toggles the map view) (`SpireStation.EnterGunnerView`): its own camera just past the model's top, the mouse captured and turning the view (`_Input`, so the hidden cursor's clicks never reach the HUD), a crosshair, and the Spire's **mortar** fires where it points (`GunnerAim`; at the sky, its reach straight ahead). The playtest liked how it shot but found the straight cannon "kinda weird... more like a mortar or trebuchet": shells now leave just under the view, left and right in turn, at the same rate, and are lobbed (`LobShell`: up to `lobApex` + `lobApexPerUnit` x the reach over the higher end, falling at `lobGravity`, about a second in the air), so they drop into canyons over the walls; a dotted arc of beads shows the path from the muzzle (`ShowArc`; none within 3 of the eye) and the marker on the ground is the blast's ring (`splash` 2.2); each bursts on landing (`LandCannon`). The marker is exactly where the crosshair's ray meets the ground (`VineGrid.RayToGround`, bisected to the surface) and the beads run all the way to it: the playtest found "aiming over hills doesn't work, the reticle and circle don't align" (the old march stopped up to two units past a wall face and snapped to the height there, off the crosshair, and the beads stopped 26 steps along the arc, in the air). Then the playtest asked for it to "shoot anywhere, but it should be slow and the projectile should be slow like a flying rock so players have to time it": reach 200 (the whole map; aimed at the sky it lands on the map's edge that way, `MapSpan`), a rock every 1.8 s (0.45) hitting for 110 in 3.0 (30 in 2.2), a high slow arc (`lobApex` 4 + 0.25 a unit, `lobGravity` 14: two to four seconds in the air), the shell a tumbling faceted rock with embers in its cracks and a dust trail (`LobShell.Fire(..., rock: true)`, `shellSize` 2.4), and no lead: it lands where it was aimed (`Lead` is gone). Past a reach shorter than the map the crosshair dims and "OUT OF RANGE: lands on the ring" shows under it (tests `spire/gunner_marker_on_the_crosshair`, `spire/gunner_reaches_the_whole_map`, `spire/mortar_is_slow`). Before, shells were straight slugs (`VfxFactory.SpawnSlug`), and before that a lightning arc from the Spire's top behind the camera. Its damage grows with BIT's levels (`MechProgression.DamageGrowth`). A held trigger is dropped when the button isn't down (it kept firing after the menu closed); climbing out, a pause (`NotificationPaused`) or leaving the scene gives the mouse back.
- **The maze:** walkers follow a flow field (`VinePathfinder.BuildFlow`: Dijkstra out from the Spire with A*'s step costs, rebuilt with `Version` bumped on every placement, sale or terrain change), so the route is whatever the towers and walls leave open, never a beeline past them. They cut corners between flow cells when the straight line is clear (`FollowFlowFromHere`, string pulling); Ghosts and flyers ignore it. `PathPreview` draws the route as chevrons marching to the Spire (strong while building, faint during waves) with a "ROUTE N cells (+M from your maze)" label, and the build ghost previews the route as it would be with that cell built on (`PreviewPath`). It redraws whenever the set of open entries changes as well as on the pathfinder's version (it waited for the lazily rebuilt flow field), and a route that opens is drawn over in gold for 10 s with NEW ROUTE on its label and an announcement (the playtest: "the enemy path lines don't update when enemies come from new locations"; `canyon/new_route_draws_its_path`, in the build and mid-wave).
- **Ascendants** (`AscendantManager`, `Ascendant`, `Data/ascendants.json`): from `min_wave`, a cleared wave can roll one. It is announced at once and named on the wave card, then comes with the next wave as a boss `VineEnemy` (`VineWaveManager.SpawnAscendant`: its own model at `model_height` with a rim in its colour, a name tag, health growing `hp_per_wave` past `min_wave`) that walks the maze to the Spire; towers, BIT and the Spire's guns hit it. `friendly_delay` seconds later its rival, a friendly `Ascendant` in its own model, comes from the Spire's side, walks to it and fights it (the enemy hits back at full `damage`; towers and BIT take `tower_damage_share` of it). Killed: its `reward` drops, a perk point, a centre-screen moment naming who made the kill (`VineEnemy.HitSource`/`LastHitBy`: BIT, your towers, the Spire or the rival), the friendly stays `friendly_linger` s swatting stragglers then walks off, and after 10 runs the body lies there for BIT to inhabit (`AscendantInhabit`, F within 8 units). Through to the Spire: it takes `spire_damage_share` of the Spire's health and leaves. A fallen friendly costs nothing by itself (it used to mean 120 a second to the Spire for 5 s). The Void Architect uses `rustbucket.fbx` (gun_robot's clips tumble it over); the Deep Current moved from `sparkplug.fbx` to `gun_robot.fbx` when Mike became BIT's body.
- **Perk tree** (`MetaPerkTree.cs`, `MetaPerkTreeScreen`, `Data/perk_tree.json`): three lanes (Towers, BIT, Spire), each a ladder whose rows open once enough points are spent higher up the lane (`needs`, counted from the rows above, so a rank can't be taken back while a row below depends on it). - **Relics** (`Data/relics.json`, `RelicRegistry`, `Scripts/VineLogic/Relics/`): each one changes how something fights, with a trade-off, and takes the one slot of its kind (`RelicInventory.Equip` takes off the one already there). - **Camera shake** is a trauma model (`TDCamera.ShakeTrauma`): shakes add trauma that decays, the offset grows as trauma^1.5 up to `SHAKE_AMPLITUDE`, small shakes (ordinary deaths) are capped at `SHAKE_MINOR_CAP`, so a pile of deaths at once doesn't throw the view around, and each big shake within `SHAKE_FATIGUE_MS` of others counts for less (`SHAKE_FATIGUE`). The Spire shakes by how hard it was hit (every hit shook hard once it was below 87%), and commanders (carried as bosses) only rumble when they die; late waves had the screen shaking without a break.
- **Pacing and safe rooms (2026-10, `WavePacing.cs`, `Data/wave_pacing.json`):** the playtest found hitting Send Wave after every easy early wave annoying. After `firstWaveDelay` (30 s) waves 1 to `continuousUntil` (20) run back to back (`continuousGap`, 2 s after each clear); after that each clear gives `laterGap` (45 s, the next wave starting by itself; Space still sends early). Safe rooms, as in Dungeon Crawler Carl: clearing wave `safeRoomFrom` (20) and every `safeRoomEvery` (10) after, if BIT has crates, the fighting stops completely (`VineWaveManager.EnterSafeRoom`: every crate waiting in the field comes to BIT, the timer stops, a SAFE ROOM celebration, the wave label says to open them); OPEN EVERYTHING (O) opens every crate in one mass opening and once it's collected the 45 s break begins (`LeaveSafeRoom`); sending a wave instead keeps the crates for the next one. Crates open only there and at the run's end (`LootManager.CantOpen` says "Opens in the safe room after W20"). The balance bots open safe-room crates quietly (`LootManager.OpenQuietly`) and wait at most the gap less half a second before building. The test harness sets `WavePacing.Classic` (30 s after every clear, crates open between any waves, no safe rooms), so suites written for that don't race the next wave; `loot` turns it off to check the pacing and safe rooms.
- **Waves stack, and stacking is a bet:** Send All sends every wave up to the next milestone (multiple of `SEND_ALL_MILESTONE`, the button says "TO W15"), at most `MAX_STACKED_WAVES` waiting, each arriving `STACK_STAGGER` seconds after the last (it sent three, which read as "only sends 3 waves"). Next during a wave stacks one. A wave sent `d` waves ahead of the one being fought pays `greed_bounty_per_stack` x d more for its kills and `greed_bonus_per_stack` x d more for its clear (`Climb.GreedBounty`/`GreedBonus`, paid when the whole stack clears; "Greed paid" is announced). Each wave of a stack still pays its own XP, supply drop, Requisition charge and Ascendant roll (`GameEvents.OnWaveCleared` fires once per wave number; `OnWaveCompleted` once per clear). A chaos wave in a stack stays armed (it used to be cancelled by the next wave sent).
- **The steady climb** (`climb` in `Data/difficulty_scaling.json`, `Climb.cs`): every enemy of every wave, authored or procedural, commanders and reinforcements included, gets `Climb.Hp(wave)`: a table of (wave, multiplier) points joined log-linearly, compounding at `hp_growth_after` past the last point (x1.8 at W3, x4.5 at W10, x7 at W20, x16 at W30, x52 at W50). It is applied in `VineWaveManager.ApplyWaveScaling` when a wave is sent (that hook used the never-instantiated `DifficultyScaler`, so nothing scaled). Enemy damage grows `damage_per_wave` (`Climb.Damage`, passed to `VineEnemy.Initialize` as `damageMult`, faction defaults included; it was 0 in every surge so `damage_growth` did nothing). Procedural waves (`VineWaveLoader.GenerateWave`, the `ramp` block) keep their template's health and only grow counts (capped at `count_cap`, the rest folded into health), traits and commanders, and always carry at least two of armour, shields and flight (`EnsureMixed`), never armour and flight on one surge (every anti-air hit is light or electric, so armoured flyers were the one group nothing answered: the wall most runs hit at W33 or W34). Before 2026-10 the authored waves stayed gentle to W20 and then compounded 18% a wave: a wall around W30. Strike and Living Walls damage follow `VineWaveLoader.RampAt` (now `Climb.Hp`). **AXIS threat** (`Climb.Threat`, `threat_scale`, `threat_power` and `threat_cap` in `climb`): every enemy's health is also times 1 + (points / scale) ^ power for the perk-tree points owned (`MetaRun.PointsSpent`), capped (x1.07 at 10 points, x1.5 at 36, x2.2 at 64, x3.5 at 102; scale 56, power 1.55). A linear threat left a 36-point tree behind a new account and a 102-point tree 14 to 20 waves ahead with BIT idle; a cubic one (x1.2 at 36, x5 at 102) with BIT played put a 36-point tree past W60 and a 102-point tree level with or behind a new account, so a full tree is still stronger than none without nothing ever threatening it (a 100-point tree held the first 30 waves at 3 to 20 times what they needed); `Climb.EnemyHp` is the climb times the threat, and the wave card and help say it. Ascendants take `climb_share` of the climb (`ascendants.json`). A leak (`VineEnemy.ReachExit`) costs `leak_base + leak_per_wave x wave` (commanders and bosses times their mult), capped at `leak_cap_share` of the Spire's full health (`leak_cap_share_big` for commanders and bosses); it was 10 + a tenth of the enemy's health, so one leak at W35 ended a run. The Spire mends `spire_mend_share` of its health when a wave clears. Third pass (2026-10): a leak is 4 + 0.05 a wave and the Bruteforge Spire regenerates 0.15 a second (it was 8 + 0.6 a wave and 4 a second: the Spire was full at the start of every wave, so a run looked fine until one wave emptied it); the Spire is a run-long budget that a failing defence drains over several waves. Each procedural wave's template is scaled to the pool's mean health budget (`VineWaveLoader.Budget`; templates differed by up to four times) and carries the expected number of commanders for its depth (a roll per surge gave none one wave and four the next). `WAVE_SEED` (environment) gives every run the same procedural waves, for comparing bots. AXIS chaos berserk takes `CHAOS_TAKEN` (0.9) of every hit with `CHAOS_HP_MULT` (1.15) health (it was flat armour of a tenth of health, then 0.8 and 1.3: reinforcements stood at 2.1 times a wave's health); chaos wreckers, and berserk guns on towers, hit for their own attack times `CHAOS_WRECK_MULT` (0.6), and chaos lasts 30 s (45 s let berserkers a defence couldn't kill wreck 90 towers). A chaos wave's own enemies (and the drops drawn from them) carry `CHAOS_WAVE_HP_SHARE` of the climb.
- **Money that keeps pace** (`economy` in `Data/difficulty_scaling.json`): kill bounties grow `bounty_per_wave` (`VineEnemy.BountyScale`, fractions carried between kills); past the authored waves the clear bonus carries on from the last authored one at `bonus_growth` a wave (it jumped from 50 to 96 at W21); every clear pays `interest_pct` of banked Resources, capped at `interest_cap_base + interest_cap_per_wave x wave` (Compound Interest adds its percent and doubles the cap); resource nodes pay `RESOURCE_NODE_BONUS` growing `node_per_wave` in either mining mode (`VineHarvester.NodePayAt`); Salvage Drills pay each wave they survive; supply pricing makes each tower of a type `tower_cost_step` dearer for each of that type standing and `fleet_cost_step` dearer for each tower of any type standing (`Climb.SupplyCost`, `Climb.Fleet`; walls and drills have their own prices, and the build bar's card says what the price is up by), so mixing types is cheaper than piling up one, the field fills slower and upgrades matter. Every kill bounty is times `bounty_mult`, drops during AXIS chaos are worth `chaos_drop_mult` (it was 3), and the Spire mines and resource nodes pay only while a wave is on (waiting between waves earned as much as fighting). - **Salvage Drill** (`VineNodeType.SalvageDrill`, last in the enum since suits save it as an int; `Towers/SalvageDrill.cs`, `Data/Towers/salvage_drill.json`, upgrades `salvage_drill` in `tower_upgrades.json` with an `income` field): an economy tower on every Spire's roster. - **Power types** (`PowerType.cs`, `Data/power_types.json`): the type picked when the Spire goes down shapes the run, and its tier rises with Materials banked this run (`tiers`; mining in Materials mode, Materials-mode drops, crates; spending doesn't lower it). - **The threat readout** (`ThreatModel.cs`, the wave card): for the next wave (procedural ones too: `VineWaveManager.WaveDataAt` generates each once and keeps it, so the card shows the wave that comes), and for a stack, each enemy group (with the climb, chaos's berserk and reinforcements) is weighed against every tower's damage a second (`VineNode.GetFirepower`), how its hits land on armour and shields (`ThreatModel.HitShare`), whether it reaches flyers (`FlyerShare` of it counts), the time one enemy spends in its reach along the route it walks (slowed by tar and rams; flyers straight), time shared when groups overlap, BIT (`BitShare`) and the Spire's guns, less the towers enemy fire takes on the way (`TowersKept`). Damage over health for the weakest group gives HOLDING (>= `HoldingAt`), TIGHT or BREAKING (< `BreakingAt`), the risk of leaks and their cost to the Spire, the weak spot in words ("Flyers: nothing but BIT can reach them"), what the wave pays (bonus, greed, kills, drills, interest), when the defence as it stands breaks (up to 7 waves out) and what Send All to the milestone would bring. During a wave the card shows the next wave as if sent now, with what's still on the field. Calibration from autoplay (six runs): under 0.5x every wave leaked; 0.5 to 0.8x, 57% of waves; 0.8 to 1.15x, 22%; 1.15 to 1.6x, 15%; above 1.6x, 2%. After wrecks and tougher towers the card called BREAKING on waves that leaked nothing (raw 0.7 to 1.15x: almost never a leak), so `Uptime` (the damage calibration) is 1.6: the bands match again. Wrecks aren't counted; the card says how many there are and what repairing them costs. The Overclock cast last wave is counted (`OverclockHabit`: each tower's share of that wave under Overclock scales its damage a second) and the card says so; a player who casts none gets the plain card. Without it, a run with BIT played read BREAKING for six waves that leaked one to five.

Towers inside the Spire's dome fire `DOME_RATE_BONUS` faster and mend themselves. The build ghost says what a cell would give (`VineHUD.PlacementHint`: crew links with the per-link share and the cap, a relay in reach and that a second adds nothing). The tower panel lists each boost with its rule (`VineNode.BoostLines`: crew links counted against the cap, the relay or Overclock on it now and that only the strongest counts, the dome, and the total damage a second), and Overclock's description and the help say it replaces a relay's boost. **Veterancy** (`Data/veterancy.json`, `Veterancy`): a tower's own kills (`VineEnemy.HitTower`/`LastTower`) rank it up for more damage and rate, shown as chevrons and in its panel. **Many at once:** the tower panel's UPGRADE ALL (or Shift-click UPGRADE) takes every tower of that type a step (cheapest first, a branch copies this tower's); Shift-drag boxes towers (Ctrl or Shift-click adds one) and the panel upgrades or sells the group (`TowerInspector.UpgradeMany`, `SelectInBox`).
- **Per-frame costs:** `Roster` reads the enemies and towers (with positions) once a frame for everything that searches them; `FrameProfiler` times the hot updates when a test switches it on (`siege` prints it); `LogOnce` keeps per-spawn set-up lines out of the log (10 lines an enemy made a 6 MB log by W140). The wave label counts enemies left and says the wave ends when they're all down. `FlightRecorder` rewrites `user://logs/flight.log` every second (fps, phase, waves, enemies, objects, memory) and keeps it as `flight_crash.log` when a session ends without its "END clean" line.
- **Canyon maps (2026-10, `CanyonMaps`, `Data/Canyons/{layout}.json`):** every map a site plays is a canyon. The playtest found the open field too free ("not clear where to build what") and asked for high walls with enemies funnelling through canyons. A spec lists routes (cell points joined by straight runs, cut by a `width`-cell brush; the first point on the map edge is the entry; `opensAfter` seconds puts a shield wall on it), the Spire and its `plaza`, `wallHeight` (2.0; it was 3.5, which hid a quarter of the walkers from the play camera and had towers firing steeply down past the lip: "lower wall heights, it makes some of the firing look weird"), floor `hazards` and wall-top `ore`. Floor cells stay `Empty` (walkable, and on a canyon map not buildable: `VineGrid.IsCanyon`); wall cells touching the floor are `Cliff` (the face: nothing builds or walks there), the rest `Ledge` (build anywhere; a sold tower gives the ledge back, `_ledgeUnderNode`). The heightmap puts every corner touching the floor at the floor and the rest at the wall height plus gentle noise (fixed per map), so floors are flat and each face drops one cell. The ground shader draws steep ground as rock with the texture on the face's own plane (`cliff_mix`, cyan strata on Grid Prime), the grid lines are red on the floor, the planet's colour on the tops and faint on the faces, and a lit rail runs along every lip (`BuildCanyonLips`). The cursor marches the ray to the drawn ground (`VineGrid.PickGround`): cutting it at y = 0 picked the cell under a wall's foot. It and the gunner's aim share `RayToGround`, which bisects the last step to the surface. BIT can't climb faces or tops (`BlocksBit`), ore on a canyon map is off the routes, and raiders climb the walls to a drill (`IsClimbable` in `BodyFits`). The dome reaches `ConversionDome.CanyonReach` (1.45x) further, since the first wall tops are four or five cells from the Spire. Clicking the floor says why it takes no tower. Tower targeting and enemy fire measure across the ground (`NearestInRange`, `FindAttackTarget`): a wall top is four units over a walker, and measured straight a Brute couldn't reach any tower and a raider at its reach couldn't shoot its drill. The Barrier Wall is now the **Barricade**: on a canyon map it goes only on the floor (off the Spire's plaza, `BarricadeSpot`), never changes a route (walkable to the pathfinder, `OnCanyonFloor`), and a walker whose route runs through it stops and hits it until it breaks (Brutes twice as hard; `VineEnemy.HoldAtBarricade`); flyers, Ghosts and raiders go on. A walker held at one, or one that can't move (a test's dummy), isn't despawned as stuck. `maps` checks each canyon (nothing builds on the floor, a wall top within 5 of every floor cell, ore within 3 of the floor, faces only beside the floor); `canyon` plays one (floor refuses a tower, a tower stands at the wall's height and selling gives the ledge back, the cursor finds wall tops, walkers stay on the floor, a raider climbs to a drill, the briefing comes over comms). The four unused open layouts (conduit, forge, labyrinth, crossroads) remain as they were; `maze` plays crossroads (`VineBattleScene.MapOverride`). Tests that look for a cell beside a route use `TestCells.BesideRoute` (on a canyon the nearest wall top is two or three cells out, and it has to see the route).
- **Sight (2026-10, `Sight.cs`, `VineGrid.HasLineOfSight`):** the playtest saw enemies and friendlies shoot each other through the walls. On a canyon map nothing sees through rock: a sight line is blocked where the drawn ground rises over it (`SightBlockedAt` tests exactly where the line crosses a grid line or a cell's split diagonal, where the surface bends; the line must clear the ground by 0.15, `SIGHT_GRAZE`, so a shot down it passes over the lip). The same points see and are seen, and shots aim there: a tower's `EyePoint` (its muzzle's height over it, remembered per type for the build ghost, `Sight.EyeUpFor`), an enemy's `BodyCentre`, BIT's `ChestPoint`, an Ascendant's `SightPoint`. Towers pick only targets they see (`NearestInRange`, `Sees`, and every class tower's own search; a tower remembers, per floor cell and body height band, whether an enemy there is in sight, out of it, or depends where it stands, and only the last needs the exact line, `VineNodeSight.cs`: exact lines for every candidate doubled the towers' time at 300 towers and gave 160 ms frames; enemies use the same table for the line back, `SeenBy`), except lobbed fire and fields (`VineNode.TypeIgnoresSight`: Mortar Pit, Slag Chute, Signal Jammer, Gravity Well, Tar Sprayer, Pneumatic Ram); arcs and chains jump only between enemies in sight of each other; the Rail Lance's slug stops at rock (`Sight.End`). Enemies shoot only towers, BIT and Ascendants they see (`FindAttackTarget`) and aim at those points; an armed raider stops to shoot a drill only once it can see it, else climbs on (`RaidManager`: one stood below a wall in reach of a drill it couldn't see, out of every tower's sight, and held a bot's wave open for ten minutes). BIT's auto-fire and relic weapons pick what BIT sees, a cast drops a target that goes behind rock, and an aimed shot stops at the first rock on its line and bursts there (`RockShots`). The Spire's guns, beam and autocannons see from their own muzzles (the column's collars see over the walls round the plaza). Strikes, siege shells and the gunner's mortar need no sight. On a canyon a gun on the lip (two cells from the floor) sees 80 to 90% of the floor in its reach and one a cell further back 42 to 53%: the build ghost lights the floor cells in reach it would see and darkens the rest (`SightOverlay`, also shown with a tower's panel), and its hint says "sees N of M floor cells in reach". For a tower that hits flyers (`VineNode.TypeHitsAir`, or `CanHitAir` with its branch) it also puts a blue dot at a flyer's height (`FLY_HEIGHT` 2.4) over every cell in reach where it would see one, wall tops included (flyers cross them), and the hint adds "hits flyers over N of M cells in reach"; a ground gun's says "can't hit flyers" (the playtest: "the attackable space doesn't take into account flying units"; `sightlines/overlay_covers_flyers`). The wave card counts only the route a tower sees (`ThreatModel.Sees`, cached per tower cell and route cell until `VineGrid.TerrainVersion` changes), and the balance bots place guns only where they see the route (`BalanceStrategies.Sighted`, `FloorSeen`). Off canyon maps everything sees everything, as before.
- **Compact HUD (2026-10):** the playtest called the screen overwhelming and not helpful, so by default the top bar shows Resources, the Spire's health, the wave and the objective in a few words (the full line in its tooltip), the wave card shows the next wave's verdict (HOLDING, TIGHT, BREAKING) and one thing to fix (an Ascendant, the weak spot, else the leaks), and shield walls show only when one is about to drop. Resource node signs are a fixed size on screen (at 0.006 a unit they were a smudge from the game camera).
- **Mass builds** (`massbuild` bench: a checkerboard of 300 top-level towers, `MASS_TOWERS`, and 150 tough enemies, `MASS_ENEMIES`, held for 10 s at 1x and 3x; frame time, KB allocated a frame and collections, script time and allocation by `FrameProfiler` key, what processes every frame by class; `MASS_PROBE=1` adds a census of meshes and triangles by owner, `MASS_PROBE_MESHES=1` the heaviest meshes, and with a display `MASS_PROBE_RENDER=1` the renderer's draws with tower shadows, rims or LOD changed (`rim`: the rim left off heavy kit meshes or small parts, with close-ups), `MASS_SHOTS=<dir>` screenshots; `MASS_FREEZE_LOOKS=1` stops the turrets turning, `MASS_SAMPLE=3` samples allocation types at 3x). 300 towers ran 248 ms a frame headless (2026-10); now about 10 ms at 1x and 15 to 18 ms at 3x, no collections (with sight, 275 towers on a canyon: 7 ms at 1x, 12 ms at 3x, towers 2.2 ms of it). Left: the rim overlay (6.2M triangles and 3,800 draws at 300 towers; left off the heavy kit meshes it saves 5.3M and 2,200, but every gun body goes dark, so it stays) and per-tower procedural materials, which keep identical parts from being drawn together. ## Game Flow (Post-Pivot Target)

```
MainMenu → [Planet Select] → Territory Map (unlock sections, view suits) →
  Farming Run:
    IntroCinematic → VineDraft (choose role) →
    Place Mining Building → choose material type →
    Wave loop (continuous, escalating):
      Build phase → Wave with surges → Build phase → next wave
      Wave milestones trigger: perk selection, new entry points, map expansion
    Spire destroyed → 2s delay → Debrief (DebriefScreen: what happened, from RunRecord) → Save Suit (optional: the 8 best towers, max 3 slots) →
    Continue → Meta Hub (MetaHubScreen) →
  Boss Run (from Territory Map, or Suits → Take into ...):
    Select open boss site → pick a suit or No suit → Confirm ("RISK IT" / "FIGHT") →
    Skip draft (the suit's role) → the suit's towers wait on the build bar (KIT) → waves until boss_wave →
    Win → site cleared, bonus resources, suit kept
    Lose → the suit is lost (nothing lost without one)
  Meta Layer:
    Spend extracted resources → Territory unlocks →
    Territory gates boss sites → suits make boss fights easier →
  Next Run (more options, clearer target)
```

### Difficulty Via Directionality (Shield Wall System)
- Game starts with West entry open, N/E/S blocked by Shield Walls
- Shield walls are visible energy barriers with procedural mesh + pulse animation
- Default trigger: time-based milestones (5min / 10min / 15min)
- Flexible trigger system: `ShieldWallManager.BreakWall(direction)` callable by any system
- Trigger types: `TimeMilestone`, `WorldObject`, `UIPrompt`, `Scripted`, `Manual`
- When a wall breaks: collapse VFX, entry region activates, pathfinder recalculates, HUD announces
- Entry regions have `Active` flag — VineWaveManager and VinePathfinder only use active regions
- Shield wall configs defined in level JSON (`shieldWalls` array) or hardcoded fallback
- More entries = more enemies = more resources to extract (opportunity, not just threat)
- Build compounds over time — no rebuilds, no resets

## Narrative

**The run's story** (2026-10; the playtest said the narrative was gone) comes over one comms panel at the top centre (`Comms`): the speaker's name in their colour, one line at a time. `StoryDirector` reads `Data/story.json`: the premise on the first run, a planet's arrival the first time BIT lands there, the region's briefing and the site's line at the start of every run, beats at set waves (BIT's memory of earlier deployments by run count, who the faction is, AXIS's quarterly indifference, the canyons), a site secured, a shield wall down, and the run's end (`{wave}`, `{deployment}` = 834 + runs, `{extracted}` and the rest filled in). Pools give one line a run, in order across runs. Story lines always get their turn; AXIS's and BIT's chatter (`AXISCommentary`, `BITCommentary`: a tower placed, a leak, late waves) is dropped when the feed is busy and goes stale after 6 s. Before, AXIS and BIT had separate boxes, BIT queued a line for a quarter of every kill (minutes of them after a wave), the chaos lines went to an event nothing showed, the memory lines were never used and `{0}` was printed as is.

### BIT
Ancient AI. Been doing this exact job longer than anyone in the game has existed. T'lan Imass archetype — functional nihilism, dark dry humor, flat affect. Not a hero on a journey. Just keeps moving. Doesn't beat anyone. They become irrelevant by proximity.

BIT doesn't know it's the cleanup script. Doesn't care about AXIS. Doesn't care about the Ascendants. Just executes, moves forward, and in doing so exposes everyone else's limitations without trying.

### AXIS
Nepo baby corporation that acquired BIT without understanding what it holds. Sends urgent directives — BIT has received 847 of them. Dismissive, not dramatic. Performatively urgent about everything because it has no actual context. Creates conditions for conflict, sends BIT to resolve it, harvests the byproduct. Keeps happening "by accident."

### Ascendants
Massively overpowered AIs who believe they've ascended. Show up reactively: an enemy Ascendant comes with a wave and walks at the Spire, the friendly one responds and fights it. The friendly isn't there for you; the player is just the stage, but the stage can shoot back. Cause map chaos: terrain destroyed, entries opened, nodes caught in crossfire. Each believes they're in the most important war. None of them are.

### The Loop IS The Story
Roguelike loop is the narrative. BIT has done this before — many times — but doesn't retain memory between deployments. AXIS wipes it. Except this run, something didn't wipe correctly. Fragments bleed through. BIT starts remembering.

## Resource System

### Resources (formerly Scrap/Gold)
- Universal, always collectable
- Funds vine node placement, infrastructure
- Mining Building produces in Resources mode
- Dropped by enemies

### Materials (formerly Mana/Magic)
- Harvested resource, gated by choice
- Accumulation-based passive buff system
- Spent in per-wave-milestone shop for ability upgrades
- Three types per planet: **Chaos, Power, Environment** (planet-agnostic)

### Material Types (power types)
| Type | Identity | In play (`PowerType`, `Data/power_types.json`) |
|---|---|---|
| Chaos | Entropy | Tower hits corrode enemies (each stack, more damage taken); Shock Blast throws them back and corrodes them fully |
| Power | Amplification | Towers fire faster and reach further; Overclock lasts longer and reaches further |
| Environment | Space manipulation | Tower hits slow (`hit_slow`), cheaper, tougher walls, stronger tar and rams, richer resource nodes; Repair Pulse fortifies |

Picked when the Spire goes down; each grows by tier with the Materials banked this run (0, 100, 250, 500, 900, 1500).

### Character Material Access
- Combat characters: locked to 1 material type, double rate
- Non-attacker: can mine 2 types, strategic timing on second choice

### Enemy Traits (counters)

Surges in `Data/Waves/P#.json` can carry `"traits"`: **armoured** (light and electric hits do 30%, ordinary 75%, heavy hits and BIT's shots land in full; Shredder strips it), **flying** (keeps 2.4 above the ground and flies straight over everything at the Spire; only Flak, Tesla, the Minigun branch, BIT and the Spire's guns reach it; Flak shoots flyers first) and **shielded** (a shield of 80% of health that takes hits first, electric hits three times over and light hits half, and grows back 15% a second after 2.5 s unhit). Each tower hits as Heavy (Junk Turret, Scatter Cannon), Light (Flak) or Electric (Tesla). Waves 1 to 3 are plain; armoured comes in on wave 4, flying on 6, shielded on 7 (P2 the same), and the wave card names the trait and its answer. Trait surges carry less health (armoured 0.85, shielded 0.7, flying 0.8, flyers also 0.7 speed). Looks: armoured enemies wear a faceted gunmetal shell with an orange rim and ribs and a steel-blue health bar (on its own `ArmourRig`, sized from the body and turned with it, so hit flashes and import scale leave it alone), shielded ones a cyan bubble and a shield bar over the health bar, flyers a ground shadow and a thruster. Procedural waves stop a siege surge at `max_per_surge` (the rest goes into health). The wave card names it and says what answers it (spread out, long guns, BIT).

### Tower Upgrades

Click a placed tower for its panel (`TowerInspector`/`TowerPanel`): two levels, then one of two branches, or sell (refunds the upgrades too). `Data/tower_upgrades.json` holds costs and effects (damage, rate, range, hp, slow, buff, force; `grants` a tower perk's behaviour for that tower; `antiAir`; `kind`). Branches: Junk Turret Railgun or Minigun (anti-air and swarms with light rounds: twice the rate at half the damage, weak to armour and shields, so it no longer answers everything), Scatter Mortar or Shredder, Tesla Storm Coil or Overload, Flak Skyguard or Shrapnel, Tar Napalm or Glue, Ram Piston or Repulsor, Relay Network or Overdrive, Wall Bulwark or Spiked. A press on a tower is a pick, so BIT doesn't fire.

**Wrecks** (`VineNode.IsWrecked`, 2026-10): a tower (any Effect node but a wall, and not under Fortress Doctrine) at zero health stands as a wreck: it doesn't fire, take signals or upgrades, nothing targets it, it still blocks the maze and keeps its upgrades. `TryRepairWreck` brings it back at full health for `WRECK_REPAIR_SHARE` of what went into it (`Invested`: place price plus upgrades); a wreck sells for `WRECK_SELL_SHARE` of the usual. The HUD shows REPAIR N WRECKS by the wave buttons (`VineNode.RepairAll`, cheapest first), the tower panel repairs one or a selection, and the wave card says how many wrecks it isn't counting. `IsDestroyed` is true for a wreck (health 0), so everything that skips dead towers skips wrecks; UI that picks towers checks `IsDestroyed && !IsWrecked`. A wreck looks broken (`TickWreck`, the playtest asked for it): dark smoke rising from its top, a crackle of blue-white sparks, now and then a flame, a red ring pulsing at its foot, the model scorched (a `blend_mul` overlay with a hot flicker, `Scorch`; the old overlays come back on repair) and a pulsing "WRECKED / needs repair" label the same size at any zoom; with many wrecks each puffs less often (`WrecksStanding`). Before, it was knocked askew with a small world-size label and an ember every two seconds (`wreck/looks_broken`). Walls are still destroyed (Brutes break them). Tower health is `VINE_NODE_BASE_HEALTH` 100 (it was 50). Before wrecks, a tower at zero vanished with its upgrades and one chaos wave took 50 to 130 towers: the next wave was the end.

## Signal Power System

Sensors have a **power budget** — the number of effect nodes one signal can activate.

| Sensor | Power | Notes |
|---|---|---|
| Proximity Sensor | 3 | Standard detection |
| Type Sensor | 3 | Faction-specific |
| HP Sensor | 3 | Wounded enemies |
| Count Sensor | 4 | Group triggers |
| Timer | 4 | Fires on interval |

- Each effect node costs 1 power. Routing nodes pass through FREE.
- Signal dies when power reaches 0.

---

## Node Types (18 implemented, 8 per role via draft)

**Structural / Routing (free):** Extender, Junction, Switch, Gate (AND), Inverter, Delay, Latch

**Sensor / Input (generate signals):** Proximity Sensor, Type Sensor, HP Sensor, Count Sensor, Timer

**Effect / Output (cost 1 power each):** Damage Tower, Slow Field, Push/Pull, Loop Anchor, Buff Emitter, Signal Cannon

### Signal Chain
`Sensor → signal → vine connections → effect node (activates, -1 power) → next effect → ... → power 0`

- **Scripted** — always at a specific address
- **Random** — probability roll
- **Reactive** — triggered by player behavior (WaveClearTime, PlayerOutOfBase, more TBD)

### Behavior Types (mix-and-match with any spawn condition)
- **Elite** — hard enemy, no special mechanic (implemented)
- **AuraBuffer** — buffs nearby units (stub)
- **Rally** — calls reinforcements, changes aggro (stub)
- **Assassin** — beelines to player, ignores all threats, telegraphed (stub)

## Meta Layer (S4 — Implemented)

### Territory
- Deterministic planet section unlocks, fixed cost, no RNG
- Data: `Data/territory.json` — sections per planet with id, cost, requires, map_variants, gates_boss, boss_wave
- Persistence: `TerritorySave` → `user://territory.json` (unlocked sections, cleared bosses, total spent)
- Loader: `TerritoryLoader` with `IsUnlocked()`, `CanUnlock()`, `TryUnlock()`, `GetBossSection()`
- UI: `TerritoryScreen.cs` — code-built CanvasLayer with planet tabs, section cards, unlock/boss buttons
- Gates boss runs and opens new farming map variants

### Boss Run Mode
- `RunMode.BossRun` in `GameManager` — high-stakes mode
- Flow: Territory (or Suits' "Take into") → boss site → BossConfirmScreen (pick a suit or No suit) → StartBossRun(planet, suit or -1, site)
- Skips the role screen and plays as the suit's role (no suit: the last role picked); the suit's towers go on the build bar via `SuitKit`
- `VineWaveManager.CheckBossWaveTrigger()` fires `OnBossDefeated` at `boss_wave` milestone
- Win: section cleared permanently, bonus resources awarded
- Lose: the suit taken in is lost (`SuitManager.DestroySuit()`); without a suit nothing is lost
- UI: `BossConfirmScreen.cs`: the target, a suit picker with No suit, the kit's towers, the warning, RISK IT or FIGHT

### Suits
- A suit is a kit of the best towers from a run: up to `Constants.SUIT_KIT_SIZE` (8), by level, then branch, then kills, never walls (`SuitManager.CreateSnapshot`, taken when the run ends). Max 3 slots (`MAX_SUIT_SLOTS`); the debrief offers it with the kit named ("8 towers: 3 Junk Turret L3 Railgun, ...")
- Data: `SuitSaveData` (name, role, planet, material, site, wave, kit, consumed); `SuitNodeEntry` holds type, level and branch (the grid position is kept only for older saves). An older save's layout loads as its best towers
- In a boss fight `SuitKit` holds the kit: the build bar says KIT xN for those types, `MetaRun.PlaceCost` is 0, and `VinePlacer` places a kit tower at its level and branch (`VineNode.ApplyKit`; it sells for nothing). When a type's kit runs out the normal price returns
- Suits screen (`SuitArmoryScreen`, `ui/suit-armory/index.html`, same in the built-in fallback): how suits work, each slot's towers by name, level and branch, where it came from and what it's worth; Take into (the next open boss, `TerritoryManager.NextBossSite`), Rename, Salvage (two clicks). Before 2026-10 a suit was the exact layout pre-placed at the same cells on the boss map (skipping any that didn't fit), the screen drew it as a map, Deploy only opened the planet screen, Rename did nothing and a boss fight couldn't start without a suit
- Persistence: `user://suits.json`; tests use `SuitManager.UseInMemoryForTests()`

### Node Unlocks (NOT YET IMPLEMENTED)
- Spend meta resources to add new node types to permanent draft pool

## Hard Rules

1. All spawn, scaling, and tuning data belongs in JSON. Never hardcode.
2. Use address format `P#-W#-S#` in all logs, comments, data.
3. Commander behavior and spawn condition are always separate fields.
4. Bosses spawn at wave milestones. Commanders attach at Surge level.
5. Completion mode lives on the Wave, not the Surge.
6. Do not build on the `Gold` or `Scrap` currency names — use Resources.
7. Do not build on `Mana` or `Magic` — use Materials.
8. Textures under `Models/` and `Materials/` import with `compress/mode=2` (VRAM), `mipmaps/generate=true` and `process/size_limit` at most 1024, or 2048 for `Models/Spires/` and `Materials/`. New kit assets arrive lossless and uncapped: set these before using them and run the `textures` suite. If you edit `.import` files outside the editor, check that the editor reimported them (`textures/imported_as_vram`).
